# MiniMesh 项目立项方案

## 1. 项目名称

**MiniMesh：跨语言轻量级 Service Mesh / RPC Mesh**

## 2. 项目定位

MiniMesh 是一个以 Go 为核心语言实现的轻量级服务网格项目，用于为 Java、Python、Go、Rust 等不同语言编写的微服务提供统一的服务通信与治理能力。

项目不直接使用 Envoy 作为核心数据面，而是自行实现 Go Sidecar，以便深入实践网络代理、gRPC、服务发现、负载均衡、连接管理、限流、熔断、重试、配置推送与可观测性等后端基础设施能力。

项目重点不是复刻完整 Istio，而是实现一个结构清晰、可运行、可压测、可演示、可逐步扩展的 Mini Service Mesh。

## 3. 项目背景

在跨语言微服务体系中，不同语言往往需要分别实现：

- 服务发现
- 负载均衡
- 超时控制
- 重试
- 熔断
- 限流
- Trace 传播
- Metrics
- 配置管理

这会导致治理逻辑侵入业务代码，同时不同语言 SDK 的行为难以完全保持一致。

MiniMesh 通过 Sidecar 将这些能力从业务服务中剥离：

```text
Java / Python / Go / Rust Service
              |
          localhost
              |
         Go Sidecar
              |
       Service Network
```

业务服务只关注业务逻辑，Sidecar 负责服务间通信和治理。

## 4. 项目目标

### 4.1 核心目标

实现以下核心组件：

1. **Go Data Plane / Sidecar**
   - RPC/HTTP 请求代理
   - 服务发现
   - 连接复用
   - 负载均衡
   - Retry / Timeout
   - Circuit Breaker
   - Rate Limit
   - Metrics / Trace

2. **Go Control Plane**
   - 服务注册
   - 服务实例管理
   - Sidecar 管理
   - 配置版本管理
   - 路由规则
   - 配置实时推送
   - 健康状态管理

3. **跨语言业务服务**
   - Go Service
   - Java Service
   - Python Service
   - 后期 Rust Service / Agent

4. **可观测性**
   - Prometheus Metrics
   - OpenTelemetry Trace
   - Jaeger
   - Grafana

5. **容器化部署**
   - Docker Compose
   - Kubernetes
   - Helm

## 5. 非目标

第一版不追求：

- 完整兼容 Istio
- 完整实现 Envoy xDS
- 支持全部 L4/L7 协议
- 生产级 mTLS CA 系统
- 多集群 Mesh
- 百万级实例规模

优先保证核心链路正确和架构可演进。

## 7. 语言职责

### Go

约占项目核心代码 70%。

负责：

- Control Plane
- Sidecar
- CLI
- 服务发现
- 网络代理
- 连接池
- 治理策略
- 配置流
- Metrics

### Java

用于模拟典型企业业务服务，例如：

- Order Service
- Payment Service

验证 Mesh 对 Java 服务的透明接入。

### Python

用于模拟：

- Recommendation Service
- AI Service
- Data Service

验证动态语言服务接入。

### Rust

不在 MVP 阶段强制引入。

后期用于：

- 高性能 Agent
- eBPF 网络观测
- 高性能协议处理
- 与 Go Data Plane 进行性能对比

## 8. 初始架构

```text
                     +----------------------+
                     |   Go Control Plane   |
                     | Registry / Config    |
                     +----------+-----------+
                                |
                       gRPC Config Stream
                                |
          +---------------------+---------------------+
          |                     |                     |
          v                     v                     v
    +-----------+         +-----------+         +-----------+
    | Go Sidecar|         | Go Sidecar|         | Go Sidecar|
    +-----+-----+         +-----+-----+         +-----+-----+
          |                     |                     |
       Java                  Go Service            Python
       Order                 Inventory          Recommendation
```

etcd 位于 Control Plane 后方，承担服务注册、Lease、Watch 和配置存储。

## 9. 核心设计原则

1. **控制面与数据面分离**
2. **业务与治理能力解耦**
3. **协议优先，跨语言实现**
4. **核心机制自行实现**
5. **先正确，再优化**
6. **每个阶段必须可测试、可验收**
7. **性能优化必须由 Benchmark 数据驱动**

## 10. 最终演示目标

最终能够启动一组不同语言服务，并展示：

```text
Client
  |
Java Order
  |
Go Sidecar
  |
Go Inventory
  |
Go Sidecar
  |
Python Recommendation
```

同时能够观察：

- 服务拓扑
- 实例上线/下线
- QPS
- P95/P99 延迟
- 请求 Trace
- 负载均衡结果
- 自动重试
- 熔断
- 限流
- 配置动态生效

并通过故障注入展示 Mesh 在实例宕机、超时、错误率升高等情况下的治理行为。
